# Knee42 v13.1 Runnable Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prepare a clean local Session A branch and commit whose Knee42 v13.1 source-runtime and Windows artifacts install from a clean directory, run the 42-class entry, fail closed on tampering, and are ready for Session C to integrate Session B's new compatible model and publish the release.

**Architecture:** A tracked release specification drives one deterministic allowlist staging builder. Runtime source, a caller-supplied model component verified against a caller-trusted manifest SHA-256, pinned task assets, root/component integrity manifests, trigger provenance, golden contract, locks, and licenses are staged once and consumed by both the Python launcher and PyInstaller onedir build. Runtime behavior is separated into clock, orientation/handedness, integrity/startup, and trigger-evaluation units so each change can be test-driven independently.

**Tech Stack:** Python 3.10, unittest, PyTorch 2.13 CPU, MediaPipe 0.10.14, OpenCV 4.11, NumPy 1.26, PowerShell/cmd launchers, PyInstaller 6.21, deterministic ZIP/SHA-256 JSON manifests.

## Session boundaries

Session A scope is limited to the v13.1 runtime, entry points, packaging, clocking, trigger behavior, and release verification. User-confirmed Phase 3 data decisions and new model creation/training belong to Session B and are not modified or revalidated by Session A.

Session C integrates Session B's new compatible 42-label [1, 64, 438] model. Session B supplies it as a model component directory, and Session C supplies that directory plus a caller-trusted component manifest SHA-256 to the release builder. Session C also owns remote publication. Session A implements and verifies the component input contract without selecting, creating, training, or altering that component. Session C can supply Session B's new compatible component and version without code edits.

Session A validates runtime and packaging only with the audited default component defined in Task 6 and assembled in Task 7, or the deterministic complete fixture component; Session C performs the first build with Session B's supplied release component.

```python
@dataclass(frozen=True)
class ReleaseSpec:
    release_version: str
    app_version: str
    default_model_version: str
    input_shape: list[int]
    label_count: int
    component_manifest_name: str
    assets: Mapping[str, AssetSpec]

@dataclass(frozen=True)
class ComponentManifest:
    component_id: str
    model_version: str
    label_count: int
    input_shape: list[int]
    payload_sha256: Mapping[str, str]
    selection_ledger_sha256: str
    runtime_config_sha256: str

def verify_release_root(root: Path) -> VerifiedRelease:
    manifest = parse_sha256_manifest(root / "integrity_manifest.sha256")
    actual = relative_file_set(root)
    expected = set(manifest) | {"integrity_manifest.sha256"}
    if actual != expected:
        raise IntegrityError(describe_member_difference(expected, actual))
    verify_all_hashes(root, manifest)
    return validate_version_manifest(root / "VERSION_MANIFEST.json", manifest)
```

The tracked spec defines `default_model_version: "v11"`, the compatible model-component layout, 42-label `[1, 64, 438]` contract, official versioned hand/pose task URLs and hashes, required source layout, trigger files, and license IDs. At build time, the caller supplies the component directory and the trusted expected SHA-256 of `component_manifest.json`. The builder must verify the expected component manifest SHA-256 before parsing any self-declared fields. It then validates every declared payload hash plus `selection_ledger_sha256` and `runtime_config_sha256`. Generated `VERSION_MANIFEST.model_version` and `VERSION_MANIFEST.component_id` come only from that verified component and `VERSION_MANIFEST.model_component_manifest_sha256` binds its trust anchor alongside the exact source commit and dependency-lock hash.
