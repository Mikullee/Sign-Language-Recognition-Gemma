# 2026-09-15 自動切段候選版驗證摘要

## 結論

已修正低 FPS 結束確認卡住，加入可信膝蓋校準、有限手腕備援與每句回位重新定位。
Web 和新影片回放共用切段控制器。沿用 42 類 Transformer v12，沒有重訓或變更分類模型。

**這是可測候選版，尚未通過真人膝蓋／跨人驗收。**
現有三支影片沒有完整膝蓋協定，不能以它們估計正式膝蓋切段準確率。
操作及重跑指令見 [候選版說明](web_knee_candidate.md)。

## 1. 原問題的直接重現

相同靜止輸入、結束門檻 0.5 秒；觀察 2 秒，不重複補幀。
舊版為 `0ae3ac0` 的精確 Web 引擎快照；v13 歷史引擎未修改。

| FPS | 舊版完成確認時間 | 新版完成確認時間 |
|---|---:|---:|
| 10 | 0.500 秒 | 0.500 秒 |
| 15 | 觀察期間未完成 | 0.533 秒 |
| 17.5 | 觀察期間未完成 | 0.514 秒 |
| 30 | 0.500 秒 | 0.500 秒 |

新版以真實時間戳計算，差距在下一個實際取樣幀的範圍內。

## 2. 合成骨架：正式膝蓋流程

使用實際交付的 `configs/auto_trigger_knee_web_live.json`：

- 4 種 FPS × 3 種速度 × 2 組位置／大小，共 24 組。
- 每組兩句，加時間抖動；共 48 段正常結束。
- 每組基準版本皆為 3：初次校準一次、兩句各更新一次。
- 起點最大絕對誤差約 0.097 秒；終點最大絕對誤差約 0.141 秒，均在 0.3 秒內。
- 另外測試胸前停頓、缺雙腕、膝蓋遮擋、移位、斷流、逾時、EOF 與備援不得更新基準。

這些數字只證明合成輸入下的狀態流程，**不是對真人或不同簽者的準確率**。

## 3. 本機原片：60 組瀏覽器回放

3 支原片各 20 組受控測試，共 60 組；不是 60 支獨立原片，也不是新增人物。
使用 Chrome `152.0.7977.83`、MediaPipe `0.10.35`、VIDEO 模式、CPU delegate。
擷取前比對實際服務提供的 JS／WASM／模型 SHA-256，快取記錄瀏覽器版本與來源 SHA。

| 項目 | 結果 | 解讀 |
|---|---:|---|
| 有人工確認膝蓋協定的原片 | 0 | 不具備正式膝蓋調參／驗收條件 |
| 新版誤建立膝蓋基準 | 0 / 60 | 這批缺膝蓋影片皆維持等待 |
| 新版正常切段 | 0 / 60 | 正式邊界通過率為 N/A，不是 0% 或 100% |
| 正式膝蓋調參 | 未執行 | 保留工程候選設定，未宣稱調優成功 |
| 舊 Web 引擎邊界達標 | 1 / 60 | 含故障注入案例，只作歷史診斷 |

舊版 60 組中的漏切為 25、提前截斷為 34、逾時為 11、多切為 0；
這些指標可重疊，例如逾時亦可能計為漏切，不應相加當作失敗片數。
新版未校準的原片不適用正常邊界誤差；報告明確標為 N/A。

### 一般邊界診斷的有限調參

為檢查工具能否正確分組，另以非膝蓋設定搜尋 16 組候選。
每折把同一原片的所有擴增留在同側；排除四種刻意遺失／裁切案例，剩每原片 16 組。
此處含時間判定修正，**不是只改門檻的純消融實驗，也不是正式膝蓋模式**。
